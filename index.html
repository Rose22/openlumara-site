Features

Everything is a module. Even the shell.

Memory, the scheduler, time-awareness, the web, even your AI's personality — all of it can be switched off, until you're talking to the bare model. Or all on. You decide.

Modular by design

Every capability is a plain Python class. Toggle anything with /module, ask the AI to do it for you, or edit the config. Turn everything off — your system prompt can be empty.

Token efficiency, visible

~4,000-token system prompts, offline token counting, binary-search context trimming, and live /status & /context so you always see exactly what's being sent.

Local-first, private

Made to pair with llamacpp, koboldcpp, and ollama. Any OpenAI-compatible API works. No cloud, no portal, no phone-home — your data never leaves your machine.

Multi-channel, one brain

WebUI, CLI, Telegram, Discord, Matrix (with encryption), ntfy, and an API bridge. One memory, one personality, every surface — switch channels on the fly, or run them all at once.

Scheduler, from scratch

Cron-style jobs with recurring schedules, three prompt strategies (from full context to instruction-only), and notifications to any channel. Morning routines, reminders, daily briefings — done.

Sandboxed coder

File operations validated with tree-sitter before they touch disk — no shell required. Read-only mode, line limits, folder blacklists, and bundled templates so your AI can write its own modules.

Persistent memory

Pinned memories live in the system prompt; everything else is searchable on demand. Stored as compact msgpack. A module — so if you want amnesia, just say so.

Safe by default

Shell access is a module that's disabled by default. When enabled, it runs in a Docker container with CPU, memory, and process limits — and an internet cutoff. HTTP & web readers have domain allow/block lists.

Architecture

Small core. Infinite shape.

A hand-written core of a few hundred ideas: a manager, a context builder, a chat store, tool-call plumbing. Around it, channels and modules plug in and out.

Every module contributes tools and prompt fragments — top, middle, or end of context. Frequently-changing data (like the time) goes at the end prompt, so history never gets reprocessed. Turn order is enforced, multimodal payloads are stripped from old messages, and broken modules are quarantined so they can't break your whole agent.

Pi

Why not Pi?

  • →

    It's a terminal. Pi is a superb minimal harness — but it's a coding agent for your terminal. No web UI, no chat channels (chat lives in a separate repo), no phone notifications.

  • →

    Features are your job. Its philosophy is "primitives, not features": no MCP, no sub-agents, no plan mode, no to-dos. Memory, scheduling, and workflows are extensions you write yourself — in TypeScript.

  • →

    No permission system. Pi runs with the privileges of whoever launched it. Containerize it yourself.

  • →

    OpenLumara ships those modules. Memory, scheduler, coder, lists, characters — all in plain Python, all off by default, all toggleable with one command.

Hermes

Why not Hermes?

To be fair: Hermes is a great agent, and its cloud is fully optional. But for local-first life use, here's where OpenLumara wins:

  • →

    Local works — but slowly. Hermes fully supports local models, but context compaction and consecutive requests can make local runs slow. OpenLumara is laser-focused on token efficiency — a ~4,000-token system prompt and instruction-only scheduling keep local models fast.

  • →

    Self-hosting is "work." By their own words: a VPS, API keys, model routing, security, and upkeep. OpenLumara: clone, run, done — on a laptop, a VPS, or a GPU box.

  • →

    Coding isn't its core. Hermes points you to Cursor for deep coding sessions. OpenLumara ships a sandboxed, tree-sitter-validated coder — no shell required.

  • →

    It's built for businesses. Founders, agencies, support desks. OpenLumara is built for your life: routines, habits, memory, reminders — even for executive dysfunction.

Extensibility

A module is a class with a few methods

No build step, no manifest, no TypeScript. If you can write Python, you can extend OpenLumara. The auto-installer even handles your module's dependencies.

user_channels/notify.py 
import core

class Notify(core.channel.Channel):
    async def run(self):
        while True:
            text = input('notify> ')
            await self.on_push({'role': 'assistant', 'content': text})

    async def on_push(self, message: dict):
        print(message['content'])  # your notification!
1

Drop a file in user_modules/ or user_channels/ and enable it in the config. CamelCase class name becomes the module name, automatically.

2

Override the hooks you need: on_system_prompt(), on_end_prompt(), on_background(), on_user_message() — or none. Plain methods become tools, docstrings become tool descriptions.

3

Declare dependencies in a dependencies list and the auto-installer installs (and uninstalls) them for you.

4

Vibecode it: OpenLumara ships hand-written templates for channels and modules. Tell your AI to read one, and it can build you a new module — then audit it yourself.
